# Stack Starter

Use this skill when starting or structuring work in this repository.

## Goal

Keep one main workflow:
- GSD for planning, state, and execution
- ECC skills for implementation discipline and review
- Axon later for code graph context
- Shannon last for security testing of web apps

## Default Path

For a new project:
1. Run `$gsd-new-project`.
2. Let GSD create and maintain planning/state documents.
3. Use ECC skills only where they sharpen implementation quality.

For existing code:
1. Run `$gsd-map-codebase`.
2. Continue with the usual GSD planning and execution flow.

## Skills To Prefer

- `tdd-workflow`
- `coding-standards`
- `verification-loop`
- `security-review`
- `backend-patterns`
- `frontend-patterns`
- `api-design`
- `eval-harness`
- `e2e-testing`
- `strategic-compact`

## Boundaries

- Do not replace GSD state with ad hoc notes.
- Do not assume Axon exists unless this repo configures it.
- Do not invoke Shannon during routine implementation.
